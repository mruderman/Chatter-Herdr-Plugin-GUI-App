- **F15 (proposed number), bridge visibility:** `GET /v1/repos/{key}/board` returns every agent's `repo_root` and `cwd` (host paths) to every member, while `/v1/repos` hides `repo_root` from non-admins. Say if you would rather leave the bridge as is.
- **Name collisions, a design question (R-number to be assigned):** Chatter resolves a name it does not know exactly as the one agent whose name begins with it, so since T13 the bridge fails closed on it. A member whose handle is the start of an agent's name (member `thom`, agent `thomas-worker`) can no longer be mentioned by a restricted member, and a DM to that member is refused with 409 `ambiguous_recipient` for everyone, admins included; the same holds when a member's handle is a proper prefix of the sender's. SPEC section 6 already forbids a handle that equals an agent's name. Recommended default: leave it (the refusal explains itself, and the admin can rename), and consider in M4 refusing at add time a handle that is the start of an agent's name or has an agent's name as its start, so that the collision cannot arise. Say if you want it in M3.
- Smaller bridge observations from T2's recordings, left as they are: agents' times on `/board` are Chatter's zoneless strings (the client converts them to ISO with `Z`); the send result's `id` can be null; `max_id` counts rows the member cannot see (a client must not infer gaps from it); there is no directory-refresh route (handled client-side by `refreshDirectory()`); the read pointer is one per repo, so marking one conversation read also passes older DMs in other conversations.
