# Executor context (read at the start of every task)

Owned by the coordinator. If something here is wrong or missing, stop and report; do not edit this file.

## 1. Project
Chatter GUI: a zero-dependency Node bridge (`bridge/`) and a TypeScript web client (`client/`, milestone M3) that give Cyan Society members, human or computational, a graphical group chat over the Chatter plugin for Herdr, reached over Tailscale. Read `docs/SPEC.md` (§5 API, §6 policy, §7 client), `docs/plans/m3-client.md` (your task) and `docs/ui-contract.md` (client tasks).

Facts that govern every decision:
- Security and accessibility outrank speed. The scale is tiny (a handful of members): do not over-engineer, and never weaken a check to get green.
- The bridge never writes Chatter's SQLite. Writes go through the `chatter` CLI with an argv array, never a shell.
- Never log, print, commit, echo or put in a URL any token. Tests use throwaway tokens.
- Message text renders as plain text only: no HTML, no remote images, links shown as text.
- The bridge stays zero-dependency (`node:` builtins only). The client may use dependencies, but adding or upgrading one is the coordinator's call: stop and report.

## 3. Code conventions
- TypeScript strict. No `any` without a comment saying why. No `@ts-ignore`, `@ts-expect-error` or suppression comments to get green.
- Plain CSS with custom properties. Colour is never the only signal. No inline `style` attributes in markup (the CSP is `style-src 'self'`).
- Comments explain why, not what. No emoji in code or UI strings.
- The UI says "member" and shows kind as a badge; it never says "bot".
- Routes, error codes and event names are constants defined once per module, not repeated literals.
- API timestamps are ISO 8601 UTC with `Z`. Ids only rise, but a member's view has gaps (other people's DMs are invisible), so never infer anything from a gap.

## 4. Do not edit
Generated or discovered by convention: `client/dist/`, `client/test-results/`, `client/playwright-report/`, lockfiles.

## 5. Commands
Use absolute paths; the shell's cwd may not be where you think. Your worktree has the repo layout under its own root. The worktree isolation guard rejects some compound shell commands (`cd ... &&` chains, heredocs, loops that pipe into other tools), so run plain single commands: `git -C <path>`, `npm --prefix <path>`, and write files with the Write and Edit tools.
- Shell state does not persist between calls. Put `CHATTER_JS=/home/cyanfam/src/chatter/dist/bin/chatter.js` in front of every command that needs it. Without it the contract tests skip silently, and skipped is not passing.
- Bridge: `npm test` at the worktree root. Baseline: 30 pass, 0 skipped.
- Client: scripts in `client/package.json` (`typecheck`, `test`, `build`, `e2e`) once T0 has landed.
- Node 22.16 (needs 22.5 or later). `node:sqlite` is experimental; keep `--no-warnings`.
- Not sure about an API of Preact, Vite, Vitest, Playwright or axe? Fetch current docs: `npx ctx7@latest library <name> "<question>"`, then `npx ctx7@latest docs <id> "<question>"` (three commands at most per question). Do not rely on memory.

If it still differs, stop and report.

- Follow the plan's done-when literally. If the plan or a frozen contract is wrong or ambiguous, stop and report; do not improvise. Never edit outside your held paths to make a check pass.

- Role limits and cadence: `docs/working-agreement.md`, Executor section.

## 7. Running in parallel
Other executors work at the same time in other worktrees on disjoint paths. Run typecheck and tests scoped to your paths and say which errors, if any, came from elsewhere. Servers bind port 0 (random), never a fixed port. Temp files go in your worktree's temp directory, never in a shared fixed path.

## 8. Final report (15 lines or fewer)

- Every decision you made that the plan did not make, every assumption, every deviation.
